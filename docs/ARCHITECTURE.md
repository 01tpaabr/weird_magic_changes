# Architecture

Status: Stage (chunked terrain grid, a billion cells each way), streaming, persistence, a windowed
ASCII renderer with a WASD camera, and the time model (integer ticks, day/night, speed
control) are built, on **Bevy 0.19** since 2026-09-23 (decision 27). Actors are designed
(`ACTORS.md`, decisions 28-37) and built in its §11 order (steps 1-8 done: step 8 made rules, scenarios and packs the input). This file records
decisions that are already made and the shape the design must fit into. Rows superseded by the Bevy move are struck through and kept for the record.

| 9 | Stage is a grid stored as 64x64 **chunks**, generated on demand in any direction; each chunk holds one contiguous array per layer (`ChunkCells`); cell coords are `i32`, inside `[-WORLD_EXTENT, WORLD_EXTENT)` = a billion cells each way (Q10: nothing past it loads, scenarios and saves refuse positions past it) | The initial map has a known size but the world must grow in any direction and stream; a chunk is at once the parallel unit, the streaming unit and the save unit. Replaced the flat row-major `Vec` + row-band design of the first Stage commit. The extent (was: unbounded, which wrapped silently past 2^25 chunks) keeps every chunk inside and each neighbour of one representable, and any two positions' difference inside an `i32` | If a system needs finer parallel granularity than a chunk: split inside the chunk by rows, never re-layout |
| 10 | A loaded chunk is a **Bevy entity** with `ChunkCoord` + `ChunkCells` + `ChunkMeta` components (was: a slab with a free list); `Stage` is the directory: `HashMap<ChunkCoord, Entity>` for lookup only and `active` = `(coord, entity)` sorted by coord, the **only** iteration order allowed to affect results | Bevy stores each component type in one dense table column, so `Query<&mut ChunkCells>` *is* the slab and `par_iter_mut` the phase. Entity ids and table order depend on load history; sorting by coordinate makes every merge and the checksum independent of them. Separate components let a double-buffered phase read `CellsPrev` while writing `ChunkCells` | If the hash lookup shows up in profiles: swap for a 2-level array keyed by chunk coord |
| 11 | Two terrain layers: `Ground` (what a cell is: Soil/Water) and `Feature` (what rests on it: None/Rock) | Rock on soil and rock on water are the same rock; keeps enum products from exploding | If features need per-cell state beyond a tag: add a parallel `Vec` for that state |
| 12 | At most one actor per cell (`occupant: Vec<ActorId>`, `ActorId::NONE` = empty); since 32, plus at most one ground-cover actor (`cover`) | Movement/collision become a per-cell ownership question with no spatial index | If stacking is a game requirement: occupant becomes a head index into a per-actor linked list |
| 13 | Worldgen is a pure function of `(seed, x, y)` via `hash_cell` + value noise; no sequential state. A scenario's drawn map (step 8e) is one more input, kept in the save header: its cells replace the noise inside it, its `outside` fill beyond it | Bit-identical for any thread count *and* any chunk size; the test recomputes every cell serially | If gen needs global passes (rivers, erosion): those become phases with their own determinism tests |
| 14 | Rendering lives in `app` (`render/`); `sim-core` has no glyphs or colours. `palette.rs` is the one place a tile becomes (glyph, fg, bg): the ground picks the cell background, the thing on it picks glyph + foreground | Layering; a system never needs to know how it looks | If tiles get per-cell scalar visuals (moisture tint): palette takes the scalar layers as input |
| 15 | Streaming: `World::ensure_loaded(focus, LoadPolicy)` loads chunks within `load` chunks of the focus and unloads beyond `unload` (`unload > load` = hysteresis). Only loaded chunks simulate. Each chunk streams on its own: a saved chunk file that fails to read or check is left unloaded and never generated over (`sim::Unreadable` remembers it, later passes skip it), the rest load and generate, the unload pass runs, and the call returns an error naming the bad files, once | Loaded set is a pure function of inputs, so replays stay bit-identical; the camera is just one source of focus. One bad file must not stop the world streaming, and generating over it would destroy the evidence | When actors wander off-screen: add per-actor focus points (or a "simulation bubble") to the same call |
| 16 | Persistence = a directory: `world.wmc` meta + `chunks/<x>_<y>.wmcc`, raw little-endian layer dumps, atomic rename on write. **Only dirty chunks are written**; clean ones are regenerated from the seed | Zero-copy format (memcpy of `ChunkCells`), saves of an unexplored world are bytes not megabytes. `FORMAT_VERSION` + `CHUNK_BITS` fingerprint refuse mismatched files | When a save has thousands of chunk files: region files (32x32 chunks per file with an offset table) |
| 17 | Camera is app state, saved in `camera.txt` beside the world, not inside the sim | The sim must not know where a player is looking; several viewers must be possible | Never |
| 18 | A frame is two pure phases plus the GPU: `cells::render_cells` (chunk lookup + viewport -> `CellFrame`, three SoA `Vec`s glyph/fg/bg, **row-band-parallel** on the compute pool, one chunk lookup per row-chunk span) then `grid::upload` (`CellFrame` -> two `TilemapChunkTileData`: solid box tinted by bg, glyph box tinted by fg). Bevy draws each layer in one call from the glyph tileset (an array texture). No reduction anywhere, so the cell phase is bit-identical for any thread count (tested); the pixels are the GPU's | Same shape as a sim tick (read shared, write owned slices). The CPU blit (Zig, band-parallel, `blit_reference` oracle) is gone: the GPU is where a 3.7 Mpx frame belongs, and `TilemapChunk` already is "a grid of tinted glyphs" | If tile upload (14k `TileData` per layer per frame) ever shows in a profile: only re-upload changed rows, or write the packed tile texture directly |
| 19 | Window = Bevy (`DefaultPlugins` trimmed to winit, 2D sprite rendering, assets, log) + `fontdue` for the glyph tileset. `wmc show`/`wmc run` are headless: a bare `bevy_ecs` `World`, no `App`. `palette::Color` stays a packed `0x00RRGGBB` `u32` (4 bytes per cell in the frame buffers) and becomes a `TileData` tint at upload; `Color::tint` pre-linearises because the tilemap shader multiplies by the tint's raw bytes without sRGB decoding | Bevy's renderer replaces softbuffer + the Zig blit; the frame buffers stay flat and small. (`pixels` 0.17 was blank on macOS; Bevy's wgpu path presents fine) | If glyphs beyond ASCII are wanted: the tileset becomes a map from char to layer |
| 20 | Glyph tileset: bundled JetBrains Mono NL (OFL, `crates/app/assets/`) rasterized once per **physical** cell size into square `cell x cell` coverage boxes for printable ASCII plus one solid box, uploaded as a `LAYERS`-layer RGBA8 array texture (white, coverage in alpha). Cell = logical 16 px x window scale factor; the camera projection is scaled so one world unit is one physical pixel and tiles display 1:1; `+`/`-` zoom rebuilds the tileset and re-inserts the (immutable) `TilemapChunk`s. Bevy's loop runs continuously at the display rate | Square cells for a top-down grid; per-physical-pixel tileset means crisp text on Retina; bundling makes the picture identical on every machine; a continuous loop is what a running sim needs anyway | When Unicode glyphs are wanted: tileset becomes a map from char to layer |
| 21 | Camera is a fractional cell position with velocity (`camera.rs`): held keys set a direction, diagonals are normalised, speed eases in/out with a 70 ms time constant, wall-clock `dt` clamped to 100 ms. The map tile layer is built one cell larger than the window and its `Transform` is shifted by the sub-cell pixel remainder (`map_layout` + `Layer::place`); the status rows are a second, unshifted layer at the bottom | Smooth scrolling without touching the cell phase or the sim: the camera is app state and its clock never reaches the sim world. Moving a transform is free; the GPU clips | When actors are followed by the camera: the target becomes an actor position, same easing |
| 22 | **Time is integers.** `World::tick: u64`; durations are tick counts; progress is an integer accumulator. `TICKS_PER_DAY = 21_600` (`sim_core::time`: 15 ticks per in-game minute, 900 per hour), a new world starts at 06:00. Calendar (`Clock::at`) and sunlight (`daylight`, 0..=255, one-hour linear ramps at 06:00 and 17:00) are **derived** from the tick, never stored. Content durations go through `minutes()/hours()/days()` | No float drift, no reduction-order dependence, exact `catch_up(n) == n x step()`. A 24 h x 60 min clock on whole ticks needs ticks/day divisible by 1440 at a 45 min real day, so the tick rate at 1x had to be a multiple of 8; 8 is the coarsest, which keeps fast-forward cheap and reads as discrete turns | If sub-4-in-game-second resolution is ever needed: 16 or 32 TPS keep the clock arithmetic exact; saves refuse the mismatch and content constants are all in in-game units |
| 23 | **Tick, cadence, speed are three different things.** Tick = the atomic step. Cadence = how often a system/entity does work: every `k` ticks, `k` a power of two, ~~staggered by a hash of the **chunk coordinate** (never the slab slot) so each tick touches `1/k` of the chunks; the helper lands with the first system that needs it (the tree)~~ staggered by a stable id, never the slab slot: a hash of the chunk coordinate for cell systems (`stage::scent::chunk_due`), the actor's `uid` for actors (`systems::due`, decision 28). Speed = real ticks per second: an `app` concern (`app::clock`, `BASE_TPS = 8` at 1x, steps 1/2/4/8/16x and max), the sim never sees a wall clock | Responsiveness and per-tick cost are cadence questions, fast-forward is free, and the sim is bit-identical at every speed and on every machine | Never; if cadence stagger ever needs to be per entity instead of per chunk, it still hashes a stable id, not memory position |
| 24 | Driver = fixed-timestep accumulator (`app::clock::SimClock::run`, a resource driven from an exclusive `Update` system; **not** Bevy's `FixedUpdate`, which cannot drop debt, cap a frame or run "as fast as possible"): ticks owed grow by `dt * tps`, whole ticks run, the fraction carries, `dt` clamped to 250 ms; ticking stops when the frame's `TICK_BUDGET` (10 ms) is spent and the **remaining debt is dropped**; `max` ticks until the budget is spent. `space` pause, `.` step-and-pause, `[`/`]` speed | A slow machine runs slow instead of spiralling; a stall resumes instead of bursting; determinism is unaffected because only the number of steps changes | If a headless server or lockstep multiplayer needs real time: same `Clock`, no window |
| 25 | Save format v2: header carries `TICKS_PER_DAY` (mismatch = refused), each chunk file carries `last_ticked` (the world tick it was written at~~, also kept in `ChunkMeta`~~). Unloaded chunks are **frozen**; nothing catches up on load yet | Whether off-screen chunks grow while away is undecided until actors exist; recording the tick they froze at costs 8 bytes and keeps both answers open. Old dev saves are simply refused | When the actor decision lands: per-system `catch_up(elapsed)` on load, exact because time is integers |
| 26 | Day/night is rendered in phase 1 (`render_cells` takes `light: u8`): `palette::brightness(daylight)` maps sim light to `NIGHT_FLOOR (0x66)..=255` and every cell colour is scaled per channel with integer math; the status bar and the tile upload are untouched. `wmc run <dir> <ticks>` steps headless and prints rate + checksum (`WMC_THREADS=1` vs default must agree) | 14k cells per frame is negligible, keeps the tile phase pure, and the status text stays readable at night. `run` is the determinism gate and tick bench in one command | If lighting becomes per cell (torches, shade): the light becomes a per-cell layer in `ChunkCells` that phase 1 reads, same place |
| 27 | **The engine is Bevy 0.19** (2026-09-23; the Zig kernels, rayon, winit+softbuffer and the `zig-kernels` crate are gone). `sim-core` depends on `bevy_ecs` + `bevy_tasks` only; `app` on the `bevy` umbrella with trimmed features. A tick is the `SimTick` schedule: `Phase` sets chained, systems inside a phase with disjoint access (`ambiguity_detection = Error` refuses anything else), chunks iterated with `Query::par_iter_mut`. Speed/pause stay in `SimClock`; `Time` is read only for the camera and the clock. Thread count via `WMC_THREADS` -> `TaskPoolPlugin`/`init_task_pool`; the determinism gate is cross-process (`crates/app/tests/determinism.rs` runs `wmc run` with 1/3/8 threads) because the compute pool is one per process | The project was always meant to be Rust + Bevy. Bevy's executor gives system-level parallelism from declared data access, its tables give the SoA slab, `par_iter_mut` gives the chunk phase, and the renderer takes the pixel work off the CPU; the sim keeps its own clock so speed, budget and stepping stay ours and deterministic | If a system needs finer parallel granularity than a chunk entity: `par_iter_mut` over a `ChunkCells` sub-range component, never a re-layout. If Bevy's executor ordering ever shows as a perf problem: `Schedule::set_executor(SingleThreadedExecutor)` on `SimTick` is a one-liner and bit-identical |
| 28 | **Actors are rows in the chunk they stand on** (`ChunkActors` = 12-byte public `ActorPub` rows, `ChunkMinds` = 88-byte private `ActorMind` rows, both Pod, same order), never entities; `occupant` packs `(kind, slot)`; identity across ticks is a hashed `uid`, never a slot. A kind is a rules file compiled once into shared bytecode. Cadence stagger is **per actor** (`uid` low bits), amending 23's "by chunk coordinate" | The chunk already is the parallel, streaming and save unit, so actors inside it get all three for free; two components let Think read every chunk's public rows while writing its own minds; per-actor stagger moves a flock organically and a migrant keeps its rhythm. Full design: `ACTORS.md` | If the 12-byte due-scan ever shows in a profile: per-chunk "next due tick" cache, still keyed on uids |
| 29 | Unloaded chunks **freeze**: on load, every row's `last_think` and `born` shift forward by the frozen interval (`now - last_ticked`), so no need decays and nobody ages off screen | Decision 25 as it stands; off-screen populations never starve while the player is away; a reopen at the save tick is bit-identical to never stopping (tested) | If fairness to off-screen plants matters: skip the shift and add growth catch-up in the same commit (both one line) |
| 30 | Conflicts are settled by state-derived keys, never by thread or slot: in-chunk claims take the `min` key in a parallel phase, cross-chunk effects run sequentially in `stage.active()` order, and a cell contested by an in-chunk and a cross-chunk mover goes to the in-chunk one (**home advantage**) | Bit-identical on any thread count with one parallel and one sequential pass; the asymmetry touches one rare case and is documented | If a herd at a border looks wrong: the symmetric owner-resolves protocol (an Outcomes component + one more parallel pass) |
| ~~31~~ | ~~**Where worldgen starts each kind is a rules property** (`place N / D`), not a terrain parameter~~ | Superseded by 36: one placement hash per cell and integer shares out of `2^24` stay; who gets a share moved from the rules to the scenario | — |
| 32 | **Ground cover is a second actor layer** (`ChunkCells.cover`, store v7): a kind declared `cover` (grass) lives under the occupant, never blocks a move and never moves; `graze` bites it, searches match a kind or tag on either layer, `bare` = walkable with no cover; the renderer tints a covered cell's background toward the cover's colour (amends 14), so a meadow reads as a green patch under whoever stands in it. Bites apply in key order and every `eat`/`graze` gains the victim's `food` by the share of health it took (replaces the single kill credit of step 5) | Grass that walls off shores starved the chickens behind it; one more `ActorId` array (16 KB per chunk) keeps movement a per-cell ownership question and needs no new search code. Food by share lets a tuft feed without dying and a shared kill feed every biter, in an order-independent sum | If a third layer is ever wanted (items on the ground): a per-cell stack, not a third array |
| 33 | **Scent is a cell layer, not an actor**: `ChunkCells.scent` = 4 channels of `u8` per cell (store v9; 2 in v8), raised by `mark` in Apply (own cell, saturating add) and faded by `scent_decay`, the first cell system: every 16 ticks per chunk, staggered by a hash of the chunk coordinate (decision 23), `s -= ceil(s / 32)`, on the channels that hold any scent. Channel names come from the rules, numbered in first-appearance order | Broadcast without messages: many actors write, many read, no queue and no order to settle (saturating adds of non-negative values commute; the fade is pure per cell). 16 KB per chunk. Four channels leave room for packs by other authors (step 8); a fifth is a compile error rather than a silent reuse | When a creature needs diffusion (smell spreading to neighbours): a double-buffered pass with a halo, not in-place |
| 34 | **Rows move between rule sets by name, and the save is rewritten whole** (`sim_core::reload`): kinds, needs, mems, states and scent channels are matched by name between two rule sets into a `Plan`. Hot reload (`r`) remaps loaded rows in place; opening a save under other rules (step 8c) remaps each chunk as it is read. The saved starts follow the same way: a `with` keeps the needs and mems its kind still has, a need clamped to its new max; a start of a kind that is gone is kept and skipped (reported), its share keeping its interval of the draw. Either way every saved chunk file is rewritten before `world.wmc` takes the new kind table, a save at the first write to the store (save, unload or reload), so a directory never mixes two numberings; every file is read and checked before the first is written, so a bad one refuses the rewrite with nothing written. A save whose kinds the rules lack is refused | Rows hold indices, and every saved chunk shares the save's one kind table: remapping only what is loaded would corrupt what is on disk. Renaming, reordering, adding and removing kinds, needs and mems all work while playing, and adding a pack to a save just works. Opening never writes, so `run` stays read-only | When saves grow past a few thousand chunk files (region files, decision 16), or when reload has to be replayable: log it as an input. If a crash mid-rewrite matters: journal the migration |
| 35 | **Inheritance is compile-time: traits and one concrete parent, families as id ranges** (step 8a). A `trait` has no id and no rows; a kind extends at most one kind and any traits; everything is merged and each rule list resolved by the compiler, and member subs are compiled once per kind (templates), so the VM and the row format know nothing of inheritance. Kinds are numbered in pre-order over the inheritance forest, so a kind's family is the id range `k..family_end[k]`; a search decodes its predicate once (`vm::Want`) and tests each cell with two compares | Content authors (other people, in their own files) get reuse without new runtime concepts. One concrete parent keeps the family a single range; roles that cut across families are tags. Decoding once per search made family matching free, and the tick 12% faster than the per-cell decode it replaced | If a kind ever needs two concrete parents: a bitset per kind of the families it belongs to, like tags |
| 36 | **A world is made from a scenario; the rules never say where anyone starts** (step 8b). A scenario file (`scenarios/*.scenario`, own line parser) holds seed, initial size, `GenParams`, and starts by kind name: `start K n / d` shares of walkable cells, cut out of each cell's one placement hash in the order written, and `start K at (x, y)` cells. `sim::create`/`open` resolve the starts against the loaded kind table into a `Placement` (a missing kind, a trait or an unwalkable cell refuses a new world; a save skips a missing kind's starts and keeps them, decision 34); the save header keeps the scenario by name (store v9, with each kind's slot names and the scent names, for remapping by name). Amends 31 | The owner's goal: other people write kinds in their own files, and a world is terrain plus who starts where, supplied as input. Placement in the rules tied a kind to one world; by name and in written order, a world starts the same under any pack that defines its kinds, however they are numbered. The checksum does not mix the scenario: rows already carry placement | When starts need conditions (trees only near water): a `start K n / d where PRED` clause. A map drawn by hand is `map` and `legend` blocks (step 8e); starts set needs and memory with `with` |
| 37 | **Rules come in packs, compiled as one rule set with one namespace** (step 8c). A pack is a directory of `*.rules` files or one file; packs compile in the order given, files by name inside each, and a kind may extend, call and read anything in any pack. A duplicate name is an error naming both files. A save remembers its packs by absolute path and reopens with them unless `--rules` or `WMC_RULES` say otherwise | Other authors add kinds without touching anyone's files, and a mod is a directory. No `import`, `pub` or namespaces: every name is global, so collisions surface at compile time, where the fix is a rename | When two mods collide on names they cannot change: a pack prefix (`wolves::hunt`) |
| 38 | **Tests attack the whole input surface, not only the new case** (review and hardening, 2026-09-26/27). `docs/GRAMMAR.md` is the rules syntax as EBNF; `rules/gen_rules.rs` draws programs from it (any that parse, valid, lively). Property tests with a fixed seed run in `make test`: compiler properties, a simulation fuzzer (invariants every tick; checksums vs another thread count, vs save + reopen, vs reload), never-panic fuzzers for scenarios, saves and the CLI; `make fuzz` runs them with many cases from a new seed. `tests/docs.rs` runs every doc example and holds the §18 limits and the vocabulary to the code. `clippy::cast_possible_truncation` is on for both crates | A review found ~160 real bugs in ~20k lines, nearly all at edges nobody had tried: huge or corrupt input, feature interactions, docs drifting from code. Determinism is priority 1 and packs come from other authors, so rules, scenarios and saves are untrusted input. Generated cases find these in seconds; the fast tier costs about 5-10 s of `make ci` | When `make ci` grows by more than 10 s from the fast tier: fewer cases there, more in `make fuzz`. Not fuzzed yet: streaming mid-run, reload with different rules, the renderer |
| 39 | **The project is an engine and a language, not one game** (owner, 2026-10-29). What we build is the engine, the rules language and the features that let other people define their own worlds and use cases. The built-in kinds (`rules/`) and `packs/life` are example and test content. A capability a piece of content needs is added as a general one any pack can use (a sense, an action, a layer, a tool), not a special case for one kind | Restates the goal behind decisions 35-37 as the project's purpose, so that feature choices, priorities and reviews are judged by what authors can build, not by how the chicken and fox game plays | N/A |
| 40 | **Tuning a world is measured, not guessed: `wmc observe` first** (owner, 2026-10-29; step 1 of the tuning plan, decision 44). `Tally` counts every death by kind and `Cause` (killed by a kind, starved of a vital need, a rule's own `die`): a sparse list per chunk, folded each tick. `wmc observe` samples a scenario's world (every hour by default): alive, life events, deaths by cause, needs (order statistics over the alive), states, last results, and dry-run thinks of up to N actors per kind (`sim::explain_slots`, picked by a hash of uid and tick): what they decide, which rules fire. A one-screen summary and a long CSV, the same on any thread count | Tuning a world's dynamics (an agent asked for "foxes hunt more, chickens survive") had two zoom levels, one actor's think (`why`) and totals at the end (`run`), and took hours of guessing. Dynamics live in between: rates, causes of death, which rules drive the decisions. Dry runs cost the tick nothing, death causes cost only on a death; about 5% on a run | When sampled decisions are not enough: exact per-rule fire counts in the VM (a counting mode beside `TRACE`) |
| 41 | **Goals are scenario expectations over time, on several seeds** (owner, 2026-10-29; step 2 of the tuning plan, decision 44). `expect always\|never\|eventually COND`, `expect mean METRIC`, `expect mean COUNTER K per day` (a rate), over a window `from T to T` that must lie in the run before the line; checks at the window's ends and every whole game minute; `eaten K by K2` and `died K of NEED` count deaths by cause (decision 40). `seeds N` / `pass M` (and `--seeds`, `--pass`) run a test once per seed and pass on `M`. One runner, `sim::run_checks`, serves `wmc scenario`, the docs' examples and the scenario fuzzer | A goal ("foxes hunt more, hens never die out") is about a stretch of a run, on any seed, not one moment of one seed; written in the scenario, the goal and its regression test are one file. Checks every minute rather than every tick keep watching cheap (a count is a pass over the rows) | When a goal needs a rolling rate ("never fewer than 10 a day, day by day") or a trend: more window forms |
| 42 | **`wmc lab` runs worlds on threads, one thread a world; constants are its knobs** (owner, 2026-10-29; step 3 of the tuning plan, decision 44). `--set NAME=V` gives a `const` another value for a session (folded in declaration order, so later constants follow); `wmc lab --set NAME=a,b,c` runs a scenario's goals for every combination of values on each seed: worker threads take runs from a shared counter and send results back by index, so the report is the same at any `--jobs`. A run stops at its first sure failure (`run_checks_until`) unless `--full`. With one compute thread, `SimTick` runs on the single-threaded executor and `par_map`/`par_zip_mut` run inline | A tuning agent needs many cheap, comparable runs, and a knob that is not a file edit. Threads beat processes here: no result parsing, and a world on one thread each scales to every core once nothing is handed to a shared pool (31 s to 6.5 s for 12 runs on 8 cores). Constants were already global names folded at compile time: overriding one needs no new language | When variants need knobs that are not constants (a scenario's start shares, a trait argument): `--set` for scenario values, or constants passed to traits. When a sweep is too large to run whole: pruning hopeless variants, deterministically (in rounds) |
| 43 | **Tuning is a protocol an agent follows, not an optimizer** (owner, 2026-10-29; step 4 of the tuning plan, decision 44). The `/world-tuning` skill: the goal as scenario expectations, a baseline explained with `wmc observe`, one check-in with the user, a written prediction before every change, sweeps with `wmc lab`, every miss explained before the next change, the margin at -20% and +20%, the goal kept in `scenarios/tests/`, a lesson added. Its references hold the arithmetic of ticks, chances and budgets, a cookbook of mechanisms in rules idioms, and the project's lessons; a notebook per goal lives in `tuning/<goal>/` | Agents read the rules language well and the dynamics badly; blind search over knobs finds values fitted to a few seeds, with no account of why, which then break. A protocol that forces measurement, prediction and explanation turns each tuning into understanding that the next one reuses | When a tuning keeps failing in the same way: a new tool (step 5, `wmc rates`), or a mechanism the language lacks |
| 44 | **The tuning plan: five steps, done** (owner, 2026-10-29). Asked for a skill and tools so an agent can make a world behave a certain way ("foxes hunt more chickens, but chickens never die out") by reasoning and measuring, after earlier sessions spent hours tweaking blind. Steps: (1) `wmc observe` and deaths by cause (decision 40); (2) goals over time and several seeds in scenarios (41); (3) `wmc lab` and `--set` (42); (4) the `/world-tuning` skill (43); (5) `wmc rates`: each rule's dice, gates, age and action read off its source at compile time (`RuleShape`), turned into odds a think, times a day and lifespans. ## Layers

```
app         Bevy App: window / input / camera / clock / render (bevy umbrella)
sim-core    bevy_ecs World: chunk entities, SimTick schedule, phases, streaming, saves
bevy_ecs + bevy_tasks   the engine's core, no renderer, no clock
```

Dependencies point downward only. `sim-core` never knows about rendering, the window or
the engine's clock; there is no `unsafe` in the repository.

## Stage layout

```
world cell (x, y): i32     chunk = (x >> 6, y >> 6)      local = (y & 63) * 64 + (x & 63)
extent: x, y in [-WORLD_EXTENT, WORLD_EXTENT) = [-10^9, 10^9)     chunks in [-CHUNK_EXTENT, CHUNK_EXTENT) = [-15625000, 15625000)

chunk entity: ChunkCoord { x, y }                              immutable component
              ChunkCells { ground: [Ground; 4096]   u8   Soil | Water
                           feature: [Feature; 4096] u8   None | Rock
                           occupant: [ActorId; 4096] u32  NONE | standing actor
                           cover: [ActorId; 4096]    u32  NONE | ground-cover actor (grass)
                           scent: [[u8; 4096]; 4]    u8   per channel, faded every 16 ticks }   one table column = the slab
              ChunkMeta  { dirty }
Stage (resource) { index:  HashMap<ChunkCoord, Entity>            lookup only
                   active: Vec<(ChunkCoord, Entity)>              sorted by (y, x): THE iteration order }
```

A phase is a system with `Query<(&ChunkCoord, &mut ChunkCells, &mut ChunkMeta)>::par_iter_mut()`.
Cross-chunk reads come later via a second component (`CellsPrev`) so all of it is readable
while `ChunkCells` is written. Reads from systems go through `StageCells` (a `SystemParam`),
from `&mut World` through `stage::chunk`/`chunk_mut`.
Walkability: `Ground::walkable && !Feature::blocks` (soil yes, water no, rock blocks). One place
to change. Per-cell scalars (moisture, heat, mana...) are further arrays in `ChunkCells`.

Streaming per frame (`app/window.rs`): load radius = chunks needed to cover half the view + 1,
unload radius = load + 2. Unload of a dirty chunk writes it; without a store, dirty chunks stay.

The world's edge (`stage::WORLD_EXTENT`, 10^9 cells, a whole number of chunks): `ensure_loaded`
clamps its focus to the nearest cell inside and cuts its load square there, so no chunk past
it is ever generated or read. To an actor in an edge chunk the chunk beyond is simply not
loaded: its cells read as rock with nobody, a move or spawn there is `BLOCKED` (the halo and
Migrate treat it like any unloaded chunk; no extra check in the tick). The inputs that name
positions are held to it: a scenario's `start ... at` and `expect at` (an error on the line),
a save's starts, initial size, drawn map and chunk file names (the save is refused),
`place_actor` and `explain` (`wmc why`) at a cell outside (nothing there). The app camera stops
at the same 10^9.
